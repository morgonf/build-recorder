# Цели работы с библиографией

Зачем собираем и читаем статьи из этой подборки. Каждая аннотация в
[ANNOTATIONS.md](ANNOTATIONS.md) в поле «Для нас» отвечает на одну из этих целей.

## Цель 1. Эффективность трассировки сборки

Снизить накладные расходы build-recorder на перехват системных вызовов.

- Ориентир проблемы: у Buildography (ближайший конкурент) замедление сборки
  14–110 % из-за однопоточной обработки ptrace-событий; у нас сопоставимое
  узкое место.
- Направления из подборки:
  - seccomp-BPF-фильтрация в ядре — останавливать процесс только на
    open*/execve/fork/clone (`strace2020-seccompbpf`, так уже делает Buildography);
  - Syscall User Dispatch + MPK — перехват без остановки процесса
    трассировщиком (`yang2024-nexpoline`);
  - миграция на eBPF — перенос сбора в ядро (`bomfather2025-ebpf`,
    `aquila2025-telemetry`), ценой требования root/CAP_BPF и свежего ядра.

## Цель 2. Обнаружение и идентификация сущностей сборки

Повысить применимость ПО для:

1. **обнаружения и идентификации сущностей, используемых при сборке** —
   исходники, заголовки, трансляторы, конфигурация; атрибуция каждого файла
   (RPM-пакет, upstream git-коммит, вендоренная зависимость);
2. **определения бинарных файлов, используемых в сборке, но не собираемых
   из исходных текстов в её процессе** (unbuilt / prebuilt binaries,
   «phantom binary dependencies») — и не только их обнаружения, но и
   идентификации происхождения: какой OSS-проект, какая версия, каким
   тулчейном собран.

- Направления из подборки:
  - source-level идентификация вендоренных компонентов: `woo2021-centris`
    (приём «уникальной части» — кандидат на ускорение --upstream-verify);
  - binary-to-source matching для unbuilt-бинарников: `duan2017-osspolice` →
    `feng2019-b2sfinder` → `b2smatcher2021-version` (до версии компонента);
  - тулчейн-атрибуция бинарника: `rosenblum2011-toolchain`, `binprov2022`;
  - патентное поле: `patent2024-12067122` (функциональность, не описанная
    исходниками), `patent2019-10296326` (идентификация OSS-пакета по бинарникам).

## Вспомогательная цель. Позиционирование статьи о verify-build.py

- Мотивация: XZ-бэкдор (`linux2024-malware-prevention`), phantom deps
  (`harbuz2026-binarydeps`), неточность декларативных SBOM-генераторов
  (`ares2024-sbom-accuracy`).
- Контраст с альтернативными путями к доверенной сборке: in-toto (не смотрит
  внутрь шага), reproducible builds (непрактичны, исключены из SLSA 1.0),
  TEE-сборки (требуют железа).
- Наш уникальный вклад — см. финальную секцию ANNOTATIONS.md.
