# План доработок build-recorder

## Северная звезда

Дать по возможности **без вмешательства в сборку** аналитику с обоснованным
утверждением: *пакет собран полностью из исходных текстов, и в сборку не
инкорпорированы ранее скомпилированные (прекомпилированные) бинарные файлы.*

Утверждение — **условно-негативное**, не абсолютное. Точная формулировка:

> Каждый файл в поставляемом payload имеет провенанс-цепочку, наблюдённую на
> syscall-границе, упирающуюся только в (а) исходные тексты и (б) объявленный
> доверенный тулчейн; и ни один поставляемый файл по содержимому не совпадает с
> ранее существовавшим бинарником, вошедшим в сборку без такой цепочки —
> при допущениях T1…T5.

Деливерабл — не «да/нет», а классификация каждого выходного файла:

- 🟢 **GREEN** — родословная упирается только в исходники + доверенный тулчейн;
- 🔴 **RED** — инкорпорирует чужой прекомпилированный бинарник (phantom binary dep);
- ⚪ **GREY** — выход без исходной родословной (скрытый канал / дыра покрытия) или
  порождён in-process компиляцией.

**Гарантия для пакета = «ноль RED и ноль GREY».** GREY честнее ложного GREEN.

Допущения, выносимые за область (документируются, не «чинятся»):
**T1** доверие тулчейну (Thompson); **T3** скрытые каналы (сокет, встроенный блоб);
**T4** in-process компиляция JVM/.NET под запретом на вмешательство.

## Направление A — Замкнуть файловый слой (advisory → sound)

*Пока эти дыры открыты, гарантия недействительна против злоумышленника и части
легитимных сборок: одна `ln` вносит прекомпилят невидимо.*

### A1. Перехват hardlink: `link` / `linkat` 🔴 **Приоритет 1**
- **Дыра:** аудит п.3/#6 — `ln prebuilt.o out.o` даёт второе имя тому же inode:
  ни `open`, ни `read`, ни `write`. Полностью невидимо. Единственная **критическая** брешь.
- **Изменение:** добавить `SYS_link`/`SYS_linkat` в `handle_syscall_exit`
  (`tracer.c:462`) по образцу `handle_rename` (`tracer.c:340-387`): oldpath →
  hash существующего inode, newpath → новый FILE_INFO с тем же хешем, ребро
  `b:hardlink`/переиспользовать `b:rename`-механику. Учесть `AT_EMPTY_PATH` для
  `O_TMPFILE`-материализации.
- **Приёмка:** сборка, где `ln`/`linkat` вносит прекомпилированный `.o` в buildroot,
  даёт для этого файла узел с хешем прекомпилята и родословную-лист = RED.
- **Объём:** S. **Форк:** да. **Апстрим:** да (реальное улучшение покрытия).

### A2. Перехват `openat2` 🟠 **Приоритет 3**
- **Дыра:** аудит п.5 — в switch только `open`/`creat`/`openat`; `openat2`
  (raw-syscall у Go/статических бинарей) прячет read и write целиком.
- **Изменение:** добавить `SYS_openat2`; флаги брать из `struct open_how`
  (2-й аргумент — указатель, не int), прочитать поле `flags` из памяти трассируемого
  через `get_str_from_process`-подобное чтение по адресу.
- **Приёмка:** программа, открывающая файл только через `openat2`, порождает
  корректные `b:reads`/`b:writes`.
- **Объём:** S. **Форк:** да. **Апстрим:** да.

### A3. Хешировать ещё открытые записи при выходе процесса 🟠 **Приоритет 2**
- **Дефект:** S1 — hash записи берётся только на `close` (`tracer.c:502`); файл,
  записанный и не закрытый до выхода, остаётся без финального хеша
  (обработчик `WIFEXITED`, `tracer.c:683`, открытые finfo не хеширует).
- **Изменение:** в ветках `WIFEXITED` и `WIFSIGNALED` (см. B2) пройтись по
  `pi->finfo`, дохешировать открытые на запись и `record_hash`.
- **Приёмка:** файл, записанный процессом без явного `close`, имеет хеш в графе.
- **Объём:** S. **Форк:** да. **Реализовать вместе с B2** (общий обработчик).

### A4. Параметризовать хеш → SHA-256 🟠 **Приоритет 4**
- **Дефект:** S2 — только SHA-1 (`hash.c`); коллизии практичны → злоумышленник
  подгоняет прекомпилят под хеш исходно-производного файла, обходя RED/GREEN.
- **Изменение:** вынести алгоритм в конфиг/флаг (EVP уже используется в `hash.c`),
  дефолт SHA-256; учесть, что gitoid/upstream-верификация может требовать SHA-1 —
  хранить оба или сделать выбор явным.
- **Приёмка:** граф содержит SHA-256; состязательная подмена по коллизии SHA-1
  не проходит верификацию.
- **Объём:** M. **Форк:** да. **Апстрим:** да (перекликается с #153).

## Направление B — Робастность трассировки (полный и валидный граф)

*Без этого граф молча неполон/битый — а неполный граф даёт ложный GREEN.*

### B1. Не падать на нерезолвимом пути 🔴 **Приоритет 1 (дешевле всех)**
- **Симптом/корень:** `absolutepath`→NULL → фатальный `error(EXIT_FAILURE)`
  (`tracer.c:274-275`); один нерезолвимый `/sys`-путь обрывает всю трассировку
  (пустой граф). Тот же класс, что upstream **#226**.
- **Изменение:** при `abspath==NULL` в `handle_open` — `free`+`return` (skip файла),
  не фатал.
- **Приёмка:** сборка с обращением к отсутствующему пути трассируется до конца;
  граф непуст; репро #226 проходит.
- **Объём:** XS. **Форк:** да. **Апстрим:** да — **закрывает #226**.

### B2. `WIFSIGNALED` + флаш/закрытие Turtle при завершении 🟠 **Приоритет 2**
- **Дефект:** S4 — цикл `wait()` (`tracer.c:613-705`) не обрабатывает
  `WIFSIGNALED`: процесс, убитый сигналом, не учитывается, `record_process_end`
  не пишется, `running` не декрементится → рассинхрон и битый/обрезанный `.out`
  (не парсится `rdflib`). `record.c` не имеет `fclose`/`fflush`.
- **Изменение:** ветка `WIFSIGNALED` (зеркало `WIFEXITED` + дохеш открытых записей,
  см. A3); `record_stop()` с `fflush`/`fclose`, повесить на `atexit()` и на
  обработчик фатальных сигналов.
- **Приёмка:** сборка, чей потомок падает по SIGSEGV, даёт **парсимый** `.out`.
- **Объём:** S. **Форк:** да. **Апстрим:** да.

## Направление C — Слой анализа (собственно вердикт GREEN/RED/GREY)

*Замкнутый граф бесполезен без вердикта. Это отдельный слой (SPARQL/скрипт над
RDF), не трассировщик.*

### C1. Классификатор листьев графа **Приоритет 2**
- **Что:** для каждого read-листа (файл, прочитанный, но не произведённый в этой
  сборке) вердикт: **source-text** / **trusted-toolchain** / **foreign-binary**.
- **Как:** тип файла (magic/расширение: текст vs ELF/ar/PE/бинарь) + принадлежность
  тулчейну (RPM-атрибуция, уже есть в проекте: файл из пакета gcc/binutils/… =
  toolchain). Всё, что бинарное и не тулчейн = foreign-binary.
- **Приёмка:** на эталонной native-сборке все листья классифицированы; toolchain
  (`gcc`/`as`/`ld`) не помечается foreign.
- **Объём:** M.

### C2. Вердикт по каждому выходному файлу + метрика fidelity **Приоритет 2**
- **Что:** обход `выход → пишущий процесс → его reads → …` до листьев; вердикт
  GREEN/RED/GREY по классам листьев; метрика fidelity = доля не-GREEN
  (по мотивам `darkmatter2026-uncharted`).
- **Приёмка:** отчёт по пакету: список RED/GREY с путями и хешами; для чистого
  пакета — 0 RED, 0 GREY.
- **Объём:** M–L. Реализовать поверх `/build-analyze`.

### C3. Пометка выходов без исходной родословной как GREY **Приоритет 3**
- **Что:** выход, чей пишущий процесс не читал ни одного source-листа (аудит п.9 —
  сокет/скрытый канал/дыра покрытия), → GREY, а не молчаливый GREEN.
- **Приёмка:** файл, записанный из сетевого источника, попадает в GREY.
- **Объём:** S (часть C2).

## Направление E — Технологии через вмешательство (опционально, ОТДЕЛЬНО)

*Нарушает принцип «без вмешательства», поэтому НЕ входит в гарантию — только как
включаемый пользователем режим покрытия JVM/.NET, когда наблюдения недостаточно и
вмешательство допустимо.*

- E1. JVM: пост-хок обогащение по атрибуту `SourceFile` в `.class` (почти без
  флагов) → точные source→class рёбра; опц. `javac -verbose` для рёбер на classpath.
- E2. .NET: ингест MSBuild binary log (`-bl`) — гранулярность сборки = истинная
  (в C# нет пофайловых объектников).
- E3. Гибрид доверия: метаданные дают рёбра, ptrace верифицирует узлы+хеши;
  расхождение = сигнал. (В литературе как таковой не встречен → потенциальная ниша.)

Литература: `omnibor2024-adg` (тот же тупик на in-process → embedding),
`rasheed2026-hiddendeps`, `classport2025-introspection`.

## Направление P — Замыкание квантора и объявление слепых зон ✅

*Обе задачи закрывают не «улучшение покрытия», а логический дефект утверждения:
вердикт мог выдать GREEN там, где не имел права ничего утверждать.*

### P1. Сверка поставляемого payload с графом ✅ **реализовано**
- **Дефект:** `compute_verdict` квантифицировал по множеству `produced`,
  выведенному из самого графа. Файл, попавший в пакет мимо трассировки, не
  становился GREY: он просто отсутствовал, и отчёт давал 0 RED / 0 GREY.
- **Изменение:** `--payload <buildroot|список путей>`; сопоставление каждого
  поставляемого файла с графом **по git-blob хешу** (алгоритм определяется из
  трассы: sha1/sha256), с откатом на сверку по пути, когда содержимого нет
  (`rpm -qpl`). Несопоставленный файл → GREY; файл, чьё содержимое совпало с
  узлом-входом, но не с записью → GREY (ненаблюдённое копирование); fidelity
  считается по payload, а не по временным файлам.
- **Приёмка:** ✅ файл в buildroot, отсутствующий в графе, даёт GREY и назван в
  отчёте; перенесённый buildroot по-прежнему сходится (сверка по содержимому).

### P2. Детект io_uring как объявленного разрыва покрытия ✅ **реализовано**
- **Дыра:** в модели угроз io_uring не упоминался. `IORING_OP_OPENAT`/`READ`/
  `WRITE`/`LINKAT` идут через кольцо; при SQPOLL операции выполняет ядерный
  поток вообще без syscall. Проверено: файл, созданный и заполненный через
  кольцо, в графе отсутствует полностью.
- **Изменение:** `SYS_io_uring_setup`/`SYS_io_uring_enter` → предикат
  `b:coverage_gap "io_uring"` на процесс (один раз на процесс и вид);
  `provenance-verdict.py` при наличии метки запрещает GREEN и понижает выходы
  такого процесса до GREY.
- **Осознанно вне объёма:** сквозное наблюдение кольца. Требует другого backend
  захвата (eBPF, X.1) или запрета io_uring через seccomp, то есть вмешательства.
- **Приёмка:** ✅ трасса демо-программы на сырых io_uring-syscalls: прежняя
  логика → GREEN/exit 0, текущая → GREY/exit 3 с указанием разрыва.

## Порядок и зависимости

```
Приоритет 1 (замкнуть + разблокировать):  A1 (hardlink) · B1 (не падать, #226)
Приоритет 2 (полнота + вердикт):          A3+B2 (общий обработчик выхода) · C1 · C2 · D1
Приоритет 3:                              A2 (openat2) · C3 · D2
Приоритет 4:                              A4 (SHA-256)
Опционально/позже:                        E1–E3 (только если разрешено вмешательство)
```

- **A3 и B2 трогают один обработчик** (`WIFEXITED`/`WIFSIGNALED`) — делать вместе.
- Гарантия становится **sound на файловом слое** после A1 + A2 + A3/B2 (+ B1 для
  полноты графа). До этого — только **advisory**.
- Вердикт (C) осмыслен лишь на замкнутом графе → C после A1.
- Апстрим-кандидаты: **B1 (закрывает #226)**, A1, A2, A4 (#153), B2.

## Критерий готовности «гарантии»
Пакет считается прошедшим, когда: (1) граф собран без обрывов (B1/B2);
(2) файловый слой замкнут (A1/A2/A3); (3) классификатор (C1) не оставил
неразмеченных листьев; (4) отчёт (C2) даёт 0 RED и 0 GREY — при явно
зафиксированных допущениях T1/T3/T4 (D1); (5) каждый поставляемый файл
сопоставлен с графом (P1) и трасса не содержит разрывов покрытия (P2).
