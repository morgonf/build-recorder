# Члены статического архива по системным вызовам линковки

Опыт к тикету X.7 (`doc/tickets-x7-archive-members.md`). Вопрос в том, можно ли
по одним системным вызовам линковки, без флагов компоновщика и без отладочной
информации, сказать, какие члены `.a` вошли в результат.

## Запуск

```sh
experiments/ar-members/repro.sh
```

Нужны gcc, GNU ld (bfd и gold) и strace, для случая cgo ещё go. Скрипт собирает
архив из двенадцати маленьких членов `s1.o`…`s12.o` (по 1,2 КБ), линкует
программу, которая вызывает `g6` и `g9`, и разбирает трассу через
`ar_reads.py`. Работает во временном каталоге.

`ar_reads.py ЛОГ АРХИВ` печатает по каждому члену два признака.

- `full` означает, что какой-то дескриптор прочитал член целиком.
- `head` означает, что какой-то дескриптор сделал короткое (меньше 4 КБ) чтение,
  начинающееся ровно с первого байта данных члена.

Дескрипторы прослеживаются через `dup`, `dup2`, `dup3` и `fcntl(F_DUPFD)`.
Без этого второй член теряется, потому что плагин читает его через копию
дескриптора.

## Результат (2026-10-25, ALT, gcc 13, GNU Binutils 2.41, go 1.26)

| Линковка | `head` | `full` |
|---|---|---|
| ld.bfd, LTO-плагин включён (по умолчанию) | ровно `s6.o`, `s9.o` | `s1.o`…`s9.o` |
| ld.bfd, `-fno-use-linker-plugin` | ничего | `s1.o`…`s9.o` |
| ld.gold, LTO-плагин включён | ровно `s6.o`, `s9.o` | ничего (архив мапится через `mmap`) |
| ld.gold, `-fno-use-linker-plugin` | ничего | ничего |
| go, cgo с внешней линковкой | ровно `s6.o`, `s9.o` | `s1.o`…`s9.o` |

Точный признак `head` даёт не компоновщик, а LTO-плагин gcc
(`liblto_plugin.so`). Компоновщик вызывает его на каждом объекте, который решил
загрузить, включая члены архива, и плагин читает ELF-заголовок этого объекта
(16 и 64 байта с начала члена, затем таблицу секций). Драйвер gcc подключает
плагин по умолчанию, поэтому признак есть в любой сборке, где линкует gcc, и от
пакетного формата не зависит.

Признак `full` у bfd даёт только верхнюю границу. Компоновщик читает архив
буферами по 4 КБ до последнего нужного члена, поэтому маленькие члены перед ним
выглядят прочитанными целиком.

## Эталон

Для сверки годится map-файл компоновщика (`-Wl,-Map=ФАЙЛ`, разбирать под
`LC_ALL=C`), секция «Archive member included to satisfy reference by file
(symbol)». `-Wl,-t` у ld.bfd 2.41 печатает только имя архива без членов, у gold
печатает члены.

## Не проверено

clang, lld и mold на стенде не установлены. lld и mold, по всей видимости, мапят
входы, как gold, и без плагина gcc признака не дадут. Это надо проверить, а не
принимать на веру.
